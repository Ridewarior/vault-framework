# Work items

The main work-item note keeps the problem, goal, scope, and background in Overview. Completion criteria stay in that note as the final major section, so they are easy to copy to the work tracker.

Add companion links before Completion criteria. Questions, decisions, working notes, research, and execution plans can be inline or separate when useful. Create only the companions the work needs.

Use the local [properties](properties.md) and [organization](organization.md) rules. Keep actual ticket identifiers and approved scope intact.

## Completion

[Completion criteria](completion-criteria.md) separate required outcomes from the checks that support them. Finishing an implementation task does not automatically satisfy those checks.

The implementation template uses Functional requirements and Acceptance verifications. The research-work template uses Research objectives and Research validation. Research checks should establish its outputs rather than inventing software tests.

These are work-vault instructions. A personal vault can omit this document and its templates.
