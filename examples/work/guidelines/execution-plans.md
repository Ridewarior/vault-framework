# Execution plans

An execution plan tracks tasks across sessions. Keep requirements, decisions, and detailed evidence in the linked work notes.

```markdown
- [x] T1 - Find the existing authorization rules.
- [ ] T2 - Implement the agreed change.
- [ ] ~~T3 - Add the retired compatibility layer.~~
- [ ] T4 - Verify the revised request flow.
```

Give each new task the next numeric ID. Keep IDs stable when reordering tasks and never reuse them. Strike through cancelled tasks. Preserve completed entries and add a new task when finished work needs revision.

Check a task when its own deliverable is done and assessed. Full ticket verification can be a later task. Update the plan at useful checkpoints rather than after every tool call.

On resume, compare recorded progress with the current files and available evidence. A checked box records past work; it does not prove that nothing has changed since.

One coordinating agent owns a shared parent checklist. Other agents report results or use separate notes. The coordinator checks their results before marking the parent task done.
